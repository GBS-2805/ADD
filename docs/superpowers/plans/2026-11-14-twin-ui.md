# BMO Twin UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a standalone, playable browser twin of the BMO editor at `twin/`, using real open-source shader, particle, pattern, motion and 3D plugins, PNG layer compositing with blend modes, and a small set of high-quality licensed assets.

**Architecture:** A Vite + React + TypeScript app in `twin/` owns a simulated BMO document, one active plugin panel, a searchable plugin catalogue, a rendered PNG layer stack, and a full-potential effects stage. The twin is isolated from the native engine and the public `docs/` shelf. Dependencies are pinned locally. The default experience exposes every effect; a non-blocking **Native lens** labels which effects are already native-ready and which still need native work. Ark UI supplies accessible primitive behavior for the Add menu and layer inspector; the Stage/Inspector grid remains first-party CSS.

**Tech Stack:** React 19, Vite, TypeScript, Motion, Paper Shaders, tsParticles, Three.js / React Three Fiber / Drei, Rough.js, Vanilla Tilt, Lucide, Ark UI 5.40.0 headless primitives, local OFL fonts, local CC0 textures, local CC BY 4.0 SVG patterns, browser PNG layers and CSS blend modes.

Ark UI supplies accessible behavior for the Add menu and inspector, while the canvas/inspector layout remains first-party CSS. Task 13 applies the monochrome proof treatment. Where these tasks conflict with the original panel geometry or palette, the later task wins.
>

**Spec:** The product contract in this document (Goal, Constraints, Visual Direction, Twin UI Composition, Cohesion Review and Dependency Register), plus the native visual contract in `EngineTokens.kt`, `EngineEdition.kt`, `EnginePluginShelf.kt` and `EnginePluginHost.kt`. The twin mirrors the BMO interaction model but is not the native editor.

## Global Constraints

- Build the twin only under `twin/`. Do not modify the native engine, `handoff/`, `docs/index.html`, `docs/assets/**`, or any published site page. This plan file is the only file added under `docs/`.
- Full Potential is the default. Do not hide effects behind a shipping-safe gate. A **Native lens** is an optional visual filter, never a restriction.
- Pin every dependency in `twin/package-lock.json`; no remote runtime code, CDN scripts, remote shaders or remote fonts.
- Use only the licensed packages/assets in the register below. Include `twin/THIRD_PARTY.md` and local licence files. User-imported files remain user-owned; keep them in memory and never bundle, upload or persist them.
- **Ark UI boundary:** import component subpaths from `@ark-ui/react` and pin `@ark-ui/react@5.40.0`. Ark supplies behavior only: no Ark theme, no Panda CSS, no Tailwind and no copied Ark examples. The primary inspector is a normal-flow grid item; `BottomSheet`, `Drawer` and `Splitter` must not own the canvas/inspector layout. Use Ark's `Menu`, `Tabs`, `NumberInput`, `Slider`, `Switch`, `ColorPicker`, `Editable` and `Select` only where Task 12 names them.
- **Monochrome boundary (Task 13):** the twin UI and its generated default content become grayscale. Do not modify `EngineTokens.kt`, the native engine or published site files, and do not claim the native palette changed. Imported PNG layers and Native Parity's native tone/prism previews are content exceptions; every other twin-generated colour must be neutral.
- The twin is research and play, not proof of Android performance or native parity.
- Do not commit, push or deploy. Run locally and open it through the preview server.
- Do not re-run Tasks 1–11; they are the shipped baseline. Implement Tasks 12–13 as the selected follow-ons. Each checkpoint is a state check, not an approval gate.
- Keep the app fully usable at 411 × 891 and 840 × 1000. The four dock targets are at least 48 px; other controls retain the existing compact control sizing.
- Respect `prefers-reduced-motion`; pause canvas animations when the tab is hidden.
- TypeScript strict mode; no `any` in public plugin contracts. Use Node 22 LTS and npm with the committed lockfile.

## Review Focus

1. **WebGL unavailable:** every shader or 3D plugin must render a useful CSS fallback instead of a blank panel.
2. **Plugin session:** hiding a plugin preserves its local controls; closing it resets them; only one plugin panel is active.
3. **Panel occlusion:** in the compact layout the inspector/panel is a normal-flow bottom-sheet row below the Stage; at 411 × 891 and on a portrait phone its bounding box must not overlap the Stage. On short landscape phones the Stage and panel share a row so the Stage keeps a usable height. The expanded layout keeps the 344 px right-side drawer because it leaves the Stage visible at tablet width. The Add menu may overlay temporarily, but it closes on selection or Escape and returns focus to Add.
4. **Playability:** a first-time visitor can open the catalogue, search “shader”, run a plugin, change a preset and see the artboard change without reading instructions.
5. **Licence, network and import boundary:** every bundled asset has a local path and licence entry; the built app makes no external network request; imported SVGs are sanitised and cannot load remote resources.
6. **PNG layer stack:** importing a PNG creates a real layer with its own order, transform, opacity and blend mode; removing it revokes its object URL, hiding the panel does not discard it, and no PSD is parsed.
7. **Monochrome integrity:** no hue appears in the shell, inspector, catalogue, controls, default artboard or generated previews; status is understandable without colour; imported PNGs and Native Parity previews remain the documented exceptions.

## Visual Direction

The twin is a **printmaker’s workbench**, not a SaaS dashboard and not the public ADD marketing page.

- **Palette (baseline):** `#F0E7D4` page, `#E1D8C6` card, `#D6CDBD` raised panel, `#1B1212` ink, `#5F5550` dim, `#5B2A4B` plum, `#6D3558` plum hover, `#F5ECD8` paper, and `rgba(27,18,18,0.22)` rule. These are the existing ADD tokens; do not introduce a second palette. **Task 13 supersedes this palette for the twin only.**
- **Typography:** Poppins for the editor chrome and controls; Instrument Serif for the sample artboard headline; Libre Franklin for small metadata; Spectral for a secondary editorial sample. All are local OFL fonts.
- **Layout:** the artboard is the hero. At desktop widths it sits inside a restrained phone/tablet frame; on a phone browser it fills the viewport. Chrome sits at the edges and the artboard keeps its own non-overlapping work area; the Add menu may overlay temporarily. Panels are print sleeves, not generic rounded cards.
- **Plugin catalogue:** live shader thumbnails, pattern swatches and particle previews. It should feel like a physical sample tray, not a marketplace grid.
- **Motion:** only panel/dock/selection transitions. No page-load reveal sequence, no decorative scroll effects, no hover animation on every card.
- **One memorable element:** the effects tray with live previews and a physical swatch rhythm. Keep the surrounding chrome quiet.
- **Avoid:** cream-and-terracotta landing-page styling, default dashboard cards, all-caps eyebrows above every section, gradient text, generic “AI” glow, and a permanent top marketing bar.

## Twin UI Composition

The twin has one composition at every width; only the panel placement changes.

```
TwinShell
  Header: ADD / TWIN, desktop viewport switch, Native lens
  Stage: device frame, artboard, rendered layer stack, selection outline
  Inspector: selected-layer properties and layer list (Task 12)
  Dock: Select · Add · Actions · Plugins        (four 48 px targets)
    Select: close the panel and return to the stage
    Add: open the Text / Shape / PNG menu (PNG routes to Overlay Lab)
    Actions: command sheet
    Plugins: searchable plugin catalogue
  PanelSheet: one in-flow panel slot
    Inspector: Properties and Layers tabs
    Commands: searchable actions and plugin commands
    Plugins: sticky search, category chips, 2-column plugin cards
      Shader Lab · Texture Lab · Particle Field · Pattern Library
      Spatial Dock · Native Parity · Asset Shelf · Overlay Lab
    PluginHost: one active panel, RUNNING / HIDE / CLOSE
```

- **Compact (411 × 891):** header, Stage and optional inspector/panel are grid rows. The inspector/panel is in normal flow, capped at 40dvh and scrolls internally; it shrinks the Stage rather than covering it. The dock floats inside the Stage's safe area instead of owning a grid row, and moves above the panel when it opens. The plugin catalogue scrolls two columns; category chips scroll horizontally.
- **Short landscape phones:** the viewport fills the screen and the Stage and panel share a row, with the panel beside the Stage. The panel keeps its own scroll and the floating dock stays inside the Stage column, clearing both the panel and the Stage footline; this avoids squeezing the Stage under the 40dvh cap.
- **Expanded (840 × 1000):** the inspector/panel is the existing 344 px right-side drawer over the Stage; the Stage fills the frame and the floating dock shifts left of the drawer. The same plugin catalogue and panel content are used; only placement changes.
- **Real phone viewport:** the app fills the screen and hides the desktop viewport switch; the compact composition and 48 px targets do not change.
- **Asset Shelf is the material shelf:** textures, patterns, icons and imported assets; it applies a background or texture. It never creates a document layer.
- **Overlay Lab is the composition shelf:** PNG import creates an image layer, with order, visibility, transform, opacity and blend mode. It is the only PNG layer importer.
- **One inspector, one panel slot (Task 12):** the inspector manages the selected layer — text, shape or image — with name, transform, opacity, visibility and blend. Overlay Lab remains the only PNG importer. When Plugins or Actions is open, that panel replaces the inspector in the same slot; never render two panels in one slot.
- **Native lens** is a header toggle that dims `needs-native` and `browser-only` cards. It never hides a plugin or disables a control.

## Monochrome pass (Task 13)

**Direction:** an ink proof, not a grey dashboard. Black ink, neutral proof paper, hairline rules, paper grain and typographic hierarchy carry the work. Remove hue, not materiality.

**Scope:** the page ground, device frame, header, dock, panel/inspector, catalogue, controls, selection, focus, shadows, status badges, generated thumbnails and the default sample artboard. The output is a single light monochrome theme; do not add a dark-mode switch.

**Content exceptions:** imported PNG layers keep their pixels, and Native Parity keeps its native tone/prism colours so its labels remain honest. No other surface may keep hue. In particular, generated shader, pattern, particle, texture and 3D previews become neutral, including their catalogue thumbnails.

**No global filter:** do not put `filter: grayscale(1)` on the Stage or the whole app. Recolour generated content at its source; filter only texture/asset preview images. A global filter would also erase imported PNG colour and would make the export preview lie about the pixels.

|---|---|---|
| `--paper` | `#F2F1ED` | page ground |
| `--sheet` | `#FAFAF7` | device and panel sheet |
| `--card` | `#E7E6E1` | cards and controls |
| `--raised` | `#D8D7D1` | raised surfaces |
| `--ink` | `#111111` | text, strokes and active fills |
| `--dim` | `#5A5A56` | secondary text |
| `--accent` | `#111111` | primary/selected |
| `--accent-hover` | `#2E2E2C` | hover |
| `--on-accent` | `#FAFAF7` | inverse text |
| `--rule` | `rgba(17,17,17,0.24)` | structural rules |
| `--soft-rule` | `rgba(17,17,17,0.12)` | dividers |
| `--focus` | `#111111` | focus ring |
| `--shadow` | `0 18px 46px rgba(17,17,17,0.18)` | elevation |

Keep `--plum` and `--plum-hover` as legacy aliases to `--accent` and `--accent-hover` for this pass so existing rules become monochrome without a mass rename. Do not add new uses of the legacy names; rename them only where a rule is already being edited.

**Status without colour:** `native-ready`, `needs-native` and `browser-only` all use `var(--dim)` text. Distinguish them with a solid square, an outlined square and a dashed square before the label. Destructive actions use the word `Remove` plus an underline/strike treatment, not red. Selection uses a dashed ink outline; focus uses the 2 px ink ring already specified.

**Acceptance:** ink-on-paper and dim-on-paper pass normal-text contrast; no UI or generated default uses a saturated colour; status is not colour-only; imported PNG colour and Native Parity colour remain intentional and are documented in the README.

## Core Contracts

```ts
import type { ComponentType, ReactNode } from "react";

export type Reality = "native-ready" | "needs-native" | "browser-only";
export type Tier = 1 | 2 | 3;
export type Surface = "none" | "commands" | "plugins";
export type BlendMode =
  | "normal" | "multiply" | "screen" | "overlay" | "darken" | "lighten"
  | "color-dodge" | "color-burn" | "hard-light" | "soft-light"
  | "difference" | "exclusion" | "hue" | "saturation" | "color" | "luminosity";

export interface TwinPlugin {
  id: string;
  name: string;
  glyph: ReactNode;
  group: "Effects" | "Texture" | "Overlay" | "Motion" | "Native";
  blurb: string;
  tags: string[];
  reality: Reality;
  tier: Tier;
  panel: ComponentType<PluginPanelProps>;
}

export type EffectTarget = "artboard" | "layer";

export type TwinEffect =
  | { kind: "shader"; shader: string; preset: string; controls: Record<string, number | string> }
  | { kind: "texture"; preset: string; image?: string; controls: Record<string, number | string> }
  | { kind: "particles"; preset: string; controls: Record<string, number | string> }
  | { kind: "pattern"; preset: string; controls: Record<string, number | string> }
  | { kind: "solid"; hex: string };

export interface LayerTransform {
  x: number;
  y: number;
  scale: number;
  rotation: number;
}

export interface TwinLayer {
  id: string;
  name: string;
  kind: "text" | "shape" | "image";
  effect: TwinEffect | null;
  blend: BlendMode;
  opacity: number;
  transform: LayerTransform;
  visible: boolean;
  image?: { assetId: string; src: string; width: number; height: number };
}

export interface TwinDocument {
  background: TwinEffect | null;
  layers: TwinLayer[];
  selectedLayerId: string;
}

export interface PluginPanelProps {
  doc: TwinDocument;
  target: EffectTarget;
  apply: (effect: TwinEffect) => void;
  toast: (message: string) => void;
}
```

`filterCatalogue(plugins, query)` is case-insensitive and matches name, blurb, group and tags. Blank queries return the full registry in declared order.

`applyEffect(target: EffectTarget, effect: TwinEffect)` writes one preview effect to the simulated document and pushes one history entry. Applying an identical effect is a no-op. Undo and redo restore the preview without changing plugin-local controls.

`addImageLayer(file: File): Promise<string>` accepts only PNG, decodes it with `createImageBitmap`, creates an image layer with `blend: "normal"`, `opacity: 1`, `visible: true`, a centered transform and an object URL, then selects and returns the new id. `setLayerBlend`, `setLayerOpacity`, `setLayerTransform`, `setLayerVisibility`, `moveLayer` and `removeLayer` update that layer; remove selects the nearest remaining layer and revokes the removed image's object URL. PNG layers are in-memory only and never enter history or local storage.

The Native lens is a non-blocking attribute on the root: it dims `needs-native` and `browser-only` cards and shows their badges, but every plugin remains available.

### What the audit changes in the plan

- **Added:** `feral-fur@0.1.1` (MIT) as the Fur mode inside Texture Lab. It renders on text and SVG paths, has no image dependency and only animates while the strands are settling.
- **Added:** a sanitised local import in Asset Shelf for user-owned PNG/JPEG/WebP/SVG material, plus PNG-only layer import in Overlay Lab. This is how a user can bring in an Alembic still as a layer or a generated Book of Shapes pattern as a texture without the twin redistributing either source.
- **Not added:** Alembic shader code, Grainrad effects, FeralUI Gradient Builder presets, a Book of Shapes pattern pack, or any MagicPattern content.
- **Not added:** `feral-blob`, `pullcord`, `playcaptcha` and `animaps-react`; they are MIT, but they are UI toys or unrelated components, not artboard effects. `feral-fur` is the only FeralUI package that earns a place.
- **Added as a source, not a dependency:** ResourceBoy. Its exclusive textures can be used in the user's final design, but the files cannot be bundled into the public twin or uploaded to the repo. The Asset Shelf and Overlay Lab imports are the only routes; no ResourceBoy asset is committed.

## Excluded Sources

- **ShaderGradient:** no repository licence file; not used.
- **Trianglify:** GPL-3.0; not used.
- **LYGIA:** dual Prosperity/Patron licence with non-commercial terms; not used.
- **GSAP:** not a permissive open-source dependency; not used.
- **Alembic editor, Alembic Shader Lab, Grainrad, FeralUI Gradient Builder, Book of Shapes generator/MCP, MagicPattern and ResourceBoy:** not bundled as runtimes, code or asset packs. Only user-owned exports may enter through the local importer; `feral-fur` is the sole FeralUI package used. ResourceBoy's exclusive files must not be committed, uploaded to the repo or shipped in the APK; third-party ResourceBoy products are governed by their own pages.

## Handoff

The twin is a playable research surface, not the shipping editor. Its Native lens reports reality; it never converts a browser effect into a native claim. Any effect promoted to the native app needs a separate native implementation and a real-device check.

After the one-pass build, open the local preview, review the captures, and decide which one or two effects are worth a native spike. Do not change the native engine from this plan.
