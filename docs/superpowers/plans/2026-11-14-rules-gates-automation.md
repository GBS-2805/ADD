# Rules, Gates and Automation Hardening Implementation Plan

> **Execution control:** `docs/superpowers/plans/2026-11-14-phasing-plan.md` is the one-phase master plan; this document keeps the detailed rules/gates/automation steps.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make documentation claims, security posture, APK identity, web performance and motion budgets enforceable by the existing check pipeline, without weakening or duplicating a gate.

**Architecture:** Keep `tools/check_all.py` as the verdict and add small, self-tested Python gates. Fast, offline gates join the default 15; test-count claims join `--visual` after the engine suite; live headers are a separate network step because the fast path must stay offline. Security starts in report-only mode where enforcement can break the site, then moves to fail-closed once the report is clean. Performance budgets are recorded from a baseline, not guessed.

**Tech Stack:** Python 3.12 standard library, existing Node 22 / Playwright 1.65.0, JDK 17, Android 35, GitHub Actions, Vercel headers. No new runtime dependency and no SaaS scanner.

**Spec:** `AGENTS.md`, `docs/agent-reference.md`, `tools/check_all.py`, `.github/workflows/checks.yml`, `docs/vercel.json`, `app/AndroidManifest.xml`, `app/src/add/ShelfActivity.java`, `tools/check_apk.py`, and the BMO plan.

## Global constraints

- Preserve the current gates. Add gates; do not replace, skip or weaken one.
- Every new gate has a `tools/tests/test_*.py` self-test, a stable summary line and a non-zero exit on failure.
- The default `python3 tools/check_all.py` stays offline and under roughly 15 seconds on this workspace.
- Network checks (`check_headers.py`) are explicit flags/jobs, never part of the default fast path.
- No secret value is printed, logged, written to a plan, or passed as a command argument. Scanners report path, line and pattern name only.
- No new framework, hosted scanner, browser dependency or runtime package. Reuse Playwright and the pinned toolchain already in CI.
- Keep `AGENTS.md` at or below 260 lines. Put mechanics in `docs/agent-reference.md`; keep policy in `AGENTS.md`.
- A new rule is not real until its command, its test and the reference section change in the same commit.
- BMO changes the engine and release route. Claims/security tasks may run before BMO; APK and device-performance enforcement lands after BMO Task 9/11.
- Do not claim a device performance pass from Robolectric or a VM. Device numbers stay in `DEVICE-REPORT.md` / `FINAL-TEST.md`.

## Review Focus

1. **A brittle claim gate blocks honest copy edits:** matching whole prose sentences will fail on a legitimate rewrite. Match the smallest stable fact (generated byte size, page count, current baseline line), and keep historical sections free to mention old values.
2. **CSP breaks the site:** inline scripts, inline style attributes and JSON-LD exist on many pages. Start report-only, generate hashes, and do not enable enforcement until the live report is clean.
3. **A performance gate is flaky:** runtime LCP/CLS varies by runner. Make the static byte budget blocking first; keep browser timing report-only until three stable baseline runs exist.
4. **A security scanner leaks what it finds:** printing a matching token is a second incident. Redact values and test that the output contains only path, line and pattern.
5. **The gate is green but not wired:** a checker that exists but is absent from `check_all`, CI or the release path changes nothing. Each task ends with the gate in the actual command path and a deliberate failing fixture.

- [ ] **Step 3: Implement both scanners.**

  `check_secrets` scans tracked files plus non-ignored untracked files; it does not
  scan ignored scratch such as `artifacts/`. Skip generated or binary files by suffix;
  allow an explicit `docs/` example allowlist. Patterns: GitHub tokens, Vercel tokens,
  Google API keys, generic `sk-` API keys, PEM private-key headers and high-entropy
  assignments in `.env`-like files.

  `check_workflows` parses the workflow text without PyYAML. Require:
  - no `pull_request_target`;
  - `permissions:` with `contents: read` unless a job narrows it;
  - publish/handoff only on `push` + `refs/heads/main`;
  - no production secret in the `review` job;
  - `persist-credentials: false` on every checkout that does not need a push;
  - every `uses:` pinned to a full commit SHA (not `@v4`, `@v5`, `@latest`).

  `check_dependencies` rejects `+`, `latest.release` and `SNAPSHOT` in the Gradle
  files, requires an exact Vercel CLI version, requires `playwright@1.65.0` in CI, and
  requires `distributionSha256Sum` in `gradle-wrapper.properties`. It does not upgrade
  anything; it reports the file and line.

- [ ] **Step 4: Pin the workflow actions, narrow permissions and pin the wrapper.**

  Resolve each current major tag to its commit SHA, replace the ref, and add
  `permissions: contents: read` at workflow level. Keep `pull-requests: write` only in
  the review job; keep `environment: production` only on publish/handoff. Add
  `persist-credentials: false` to non-publishing checkouts. Add the Gradle wrapper
  checksum and confirm the wrapper distribution URL is an exact version.

### Task 3: Add live headers and a staged CSP

**Files:**
- Create: `tools/check_headers.py`, `tools/build_csp.py`
- Test: `tools/tests/test_check_headers.py`, `tools/tests/test_build_csp.py`
- Modify: `docs/vercel.json`, `handoff/vercel.json`
- Modify: `tools/deploy_vercel.py`, `tools/deploy_review.py` only to call the live check
- Modify: `.github/workflows/checks.yml` for the post-deploy check

**Interfaces:**
- Produces:
  ```python
  def problems(origin: str, expected: dict[str, str]) -> list[str]: ...
  ```
  Expected headers include CSP, HSTS, `X-Content-Type-Options`, `X-Frame-Options`,
  `Referrer-Policy`, `Permissions-Policy`, COOP and CORP.

- [ ] **Step 1: Write the failing header tests.**

  Use a local fixture server or `urllib` double. Cover missing CSP, CSP with
  `unsafe-eval`, short HSTS, missing frame denial, wrong cache policy on hashed assets
  and the correct live set. Test that a redirect to `http://` fails.

- [ ] **Step 2: Add report-only CSP and the missing headers.**

  Start with `Content-Security-Policy-Report-Only` on `docs/` and `handoff/`:
  ```text
  default-src 'self'; base-uri 'none'; object-src 'none';
  frame-ancestors 'none'; form-action 'self';
  img-src 'self' data:; font-src 'self'; connect-src 'self';
  script-src 'self' 'sha256-...'; style-src 'self' 'unsafe-inline'
  ```
  Add `Strict-Transport-Security: max-age=31536000; includeSubDomains`,
  `Cross-Origin-Resource-Policy: same-origin`, and
  `X-Permitted-Cross-Domain-Policies: none`. Keep the existing `X-Frame-Options`,
  COOP, referrer and permissions headers. Do not add `unsafe-eval`.

- [ ] **Step 3: Generate and verify inline-script hashes.**

  `tools/build_csp.py` extracts every inline `<script>` block and emits SHA-256 hashes.
  It must fail if a page contains an inline script with no hash in the config. The
  current pages with inline scripts include `docs/icons/*`, `docs/renders/`,
  `docs/compress/`, `docs/search/`, `docs/fonts/` and `docs/icons/all/`.

- [ ] **Step 4: Add the live gate.**

  `check_headers.py --origin https://artbase-olive.vercel.app` and the handoff origin
  must return the expected set; fail on a missing or weaker header. Run it after
  publish and in the daily live job, not in the offline fast path.

- [ ] **Step 5: Move from report-only to enforcement.**

  After one clean live report, change the header to enforcing CSP. If inline styles
  still require `style-src 'unsafe-inline'`, record that as a residual risk; do not
  describe the CSP as strict until the style attributes are extracted.

- [ ] **Step 6: Run and commit.**

  ```bash
  python3 tools/check_headers.py --origin https://artbase-olive.vercel.app
  python3 -m unittest tools.tests.test_check_headers tools.tests.test_build_csp -v
  git add tools/check_headers.py tools/build_csp.py tools/tests docs/vercel.json \
    handoff/vercel.json tools/deploy_vercel.py tools/deploy_review.py \
    .github/workflows/checks.yml
  git commit -m "security: add live header checks and a staged CSP"
  ```

### Task 5: Add static web, image and motion budgets

**Files:**

- Test: `tools/tests/test_check_web_budget.py`, `tools/tests/test_check_images.py`, `tools/tests/test_check_motion.py`

**Interfaces:**

  `problems(root=ROOT) -> list[str]`; budgets live in `tools/web_budget.json`.
- `check_images.py`: `problems(root=ROOT) -> list[str]`.
- `check_motion.py`: `problems(root=ROOT) -> list[str]`.

- [ ] **Step 1: Record the baseline before setting budgets.**

  Run a measurement over every modern page. Record:
  - HTML bytes;
  - referenced CSS/JS bytes;
  - local font bytes actually referenced;
  - local image bytes in the first viewport;
  - total referenced bytes per page.

  Set `tools/web_budget.json` to the measured value plus 10% headroom, rounded up. Do
  not invent a budget from a generic target. Keep `docs/classic/` on a separate frozen
  ceiling.

- [ ] **Step 2: Write the failing tests.**

  Cover an over-budget page, an image without `width`/`height`, a below-fold image
  without `loading="lazy"`, a second `fetchpriority="high"`, a PNG in `docs/renders/`,
  a missing reduced-motion block and a motion duration above the policy.

- [ ] **Step 3: Implement the static gates.**

  `check_images.py` requires:
  - `width` and `height` on every `<img>`;
  - `loading="lazy"` on all but the hero image;
  - exactly one `fetchpriority="high"` per page;
  - `decoding="async"`;
  - WebP/AVIF for gallery captures, not PNG;
  - a warning for an SVG over 500 KB, a hard failure over 1 MB unless listed as an
    approved artboard.

  `check_motion.py` requires a `prefers-reduced-motion: reduce` block in the shared
  stylesheet and in any page-local animation; transitions above 500 ms are a failure
  unless the selector is in a documented allowlist.

- [ ] **Step 3b: Record asset-hygiene candidates, do not guess.**

  For long generated galleries, add `content-visibility: auto` with a measured
  `contain-intrinsic-size` only after a CLS comparison. Audit optional `gsap.min.js`
  loading on pages that do not use it; remove a library only with a visual/behaviour
  test. Do not delete the Poppins TTF/woff files because they are intentional direct
  downloads; pages should still reference the smallest suitable woff2.

- [ ] **Step 4: Run the gates and wire them into `check_all`.**

  Add `budget`, `images` and `motion` to the fast rows and `VERDICT`. Run:
  ```bash

  python3 tools/check_images.py
  python3 tools/check_motion.py
  python3 tools/check_all.py
  ```
  Expected: baseline passes with the recorded budgets; all 15 existing gates still green.

## Acceptance

- `python3 tools/check_all.py` stays offline and reports all new gates.
- `python3 tools/check_all.py --visual` remains green at 175 tests / 14 goldens.
- A stale README size, page count or engine baseline fails with a precise path.
- A fake token fails `check_secrets` without printing the token.
- A workflow with `pull_request_target`, an unpinned action or a production secret in a
  PR job fails before merge.
- Site and handoff responses carry the expected CSP/HSTS/CORP set; a weaker header fails.
- The release APK is non-debuggable, signed by the allowlisted certificate and matches
  the published digest.
- The page budget and image/motion gates fail on a deliberate regression.
- No device number is claimed without a device report.

## Risks and review questions

- **CSP:** `style-src 'unsafe-inline'` is a residual risk because the pages carry inline
  style attributes. Approve a follow-up that extracts them, or accept it explicitly.
- **Action pinning:** SHA pins need periodic updates; the gate should report an outdated
  pin rather than silently accept a tag.
- **Performance:** LCP/CLS on a shared runner is noisy. Keep it report-only until the
  three-run baseline is stable; do not turn a flaky metric into a red build.
- **APK certificate:** the allowlist is public, not secret. Confirm the current signing
  certificate fingerprint before committing it.
- **Scope:** no new hosted service, no new runtime dependency and no Vercel deletion.

## Self-review

- **Coverage:** claims, secrets, workflow permissions, CSP/headers, APK identity, WebView
  network boundary, static web budgets, image/motion, runtime and engine evidence, CI
  wiring and rules are each owned by a task.
- **No fake enforcement:** every gate is added to `check_all` or an explicit live/release
  path, and has a deliberate-failure check.
- **No invented numbers:** web budgets are measured plus headroom; engine targets remain
  device-only; CSP starts report-only.
